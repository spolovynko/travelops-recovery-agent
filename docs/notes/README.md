# Phase notes

Create one learning note per completed phase:

```text
phase-0.md
phase-1.md
phase-2.md
...
```

The note is not a diary or a copy of the implementation. Codex should explain
the important mechanisms clearly and connect them to observed project behaviour.
The learner is not required to answer questions or rewrite the explanation.

## Note template

```markdown
# Phase N notes — phase name

## What this phase shipped

Describe the observable result and how to run it.

## How it works

Explain the flow from entry point to result. Link to the important files.

## Concepts I can explain

Explain each concept in plain language and relate it to this repository.

## Decisions I made

Describe judgment calls, alternatives considered, and consequences.

## Tests and demonstrations

List what was tested and what each check proves. Include manual evidence when relevant.

## What failed or surprised me

Record useful mistakes and how they changed the understanding or design.

## Remaining limitations

State what the phase deliberately does not solve.
```
